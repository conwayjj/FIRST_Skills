Overview

You program animations, not pixels

The Prism is a small LED computer that sits between the Control Hub and the LED strips. Your OpMode never sets LED colors one at a time. Instead, you send it animations (Solid, Blink, Pulse, Rainbow, Snakes, and eight more) over I²C, each one covering a range of LED indexes. The Prism then runs those animations by itself, so the lights keep moving even while your code is busy, and even after the OpMode stops.

The simulator above uses the same class names, method names, defaults, and limits as goBILDA's Java driver (GoBildaPrismDriver, PrismAnimations, Color, Direction), so code that works here can be copied onto the robot.

Our Hardware

LED index map

Four strips are daisy-chained clockwise starting at the top strip, so the Prism sees one 36-LED strip. Index 0 is the first LED of the top strip (the end the Prism plugs into).

StripLEDsIndexesRuns (facing the LEDs)
Top120 – 11left → right
Right612 – 17top → bottom
Bottom1218 – 29right → left
Left630 – 35bottom → top

Ranges are inclusive: setStartIndex(12) + setStopIndex(17) lights all 6 LEDs on the right strip. Because the bottom and left strips run "backwards" on the robot, Direction.Forward always means "clockwise" around the rectangle.

Key Ideas

How the Prism thinks

  • Layers. The Prism has 10 layers, LAYER_0 to LAYER_9, each holding one animation. Higher layers draw on top of lower ones.
  • Black is see-through. Color.TRANSPARENT is (0, 0, 0). Wherever a layer is black, or outside its index range, you see the layer below.
  • Insert vs. update. insertAnimation only stores the animation in your driver object. Nothing reaches the LEDs until you call insertAndUpdateAnimation, updateAnimationFromIndex, or updateAllAnimations.
  • Change an animation in place. Keep a reference, call its setters (setPrimaryColor, setStopIndex, ...), then updateAnimationFromIndex(layer).
  • Every update is an I²C write. Only update when something changes, not every loop. Watch the I²C / sec meter.
  • Artboards save all 10 layers into the Prism's memory (8 slots). One can be the boot animation shown at power-on.
Quick Start

The five lines you always need

GoBildaPrismDriver prism = hardwareMap.get(GoBildaPrismDriver.class, "prism");
prism.setStripLength(36);           // 12 + 6 + 12 + 6
prism.clearAllAnimations();         // layers survive between OpModes — start clean

PrismAnimations.Solid top = new PrismAnimations.Solid(Color.BLUE, 0, 11);   // color, start, stop
prism.insertAndUpdateAnimation(GoBildaPrismDriver.LayerHeight.LAYER_0, top);

Try this in order

  1. Solid Color: change the color and brightness. Make your own color with new Color(255, 80, 0).
  2. Four Strips: give each strip its own color using index ranges. Then make just the corners white on a higher layer.
  3. Layers: a Rainbow on the bottom, Sparkle above it, and a DroidScan only on the top strip. Hold A to hide the scanner.
  4. Gamepad States: a state machine that only talks to the Prism when the robot's state changes.
  5. Trigger Bar: the right trigger fills the top strip like a gauge, updating one animation in place.
  6. Match Timer: colors that change as the end of the match gets closer, using ElapsedTime.
  7. Artboards: save looks into the Prism, switch between them with X / Y, then press Power-cycle Prism to see the boot artboard.
  8. Iterative OpMode: the same ideas written with init() / loop() instead of runOpMode().

Challenges

  • Show alliance color (press X for blue, B for red) on the side strips while the top strip keeps showing robot state.
  • Make a chase that runs clockwise around all four strips, then press the D-pad to reverse it.
  • Make the bottom strip mirror the trigger gauge on the top strip. (Hint: the bottom strip runs right to left.)
  • Flash the whole rectangle white for half a second each time A is pressed (gamepad1.aWasPressed()), then go back to the previous look.
Reference

GoBildaPrismDriver

hardwareMap.get(GoBildaPrismDriver.class, "prism")
Gets the driver. The name must match the I²C device name in your robot configuration (set it in the Device box above to practice).
setStripLength(int length)
How many LEDs are on the chain (0–255). Ours is 36.
insertAnimation(LayerHeight, animation)
Stores an animation in a layer of the driver object. Sends nothing. Returns false for DISABLED or null.
insertAndUpdateAnimation(LayerHeight, animation)
Stores and sends it. The animation restarts from the beginning.
updateAnimationFromIndex(LayerHeight)
Re-sends the animation already stored in that layer, after you've changed its settings.
updateAllAnimations()
Re-sends every stored layer (one I²C write each).
clearAllAnimations()
Clears all 10 layers on the Prism and in the driver.
setTargetFPS(int fps)
Animation frame rate the Prism aims for (0–32767).
getNumberOfLEDs() / getCurrentFPS()
Read back the strip length and the frame rate the Prism is actually running.
saveCurrentAnimationsToArtboard(Artboard)
Copies all current layers into one of 8 saved slots, ARTBOARD_0–ARTBOARD_7.
loadAnimationsFromArtboard(Artboard)
Replaces the current layers with a saved artboard, with one write.
setDefaultBootArtboard(Artboard) / enableDefaultBootArtboard(boolean)
Chooses which artboard plays at power-on, and turns that on or off.
getDeviceID(), getFirmwareVersionString(), getHardwareVersionString(), getPowerCycleCount(), getRunTime(TimeUnit)
Diagnostics. In the simulator the version strings read "simulated".
GoBildaPrismDriver.LayerHeight
LAYER_0 (bottom) … LAYER_9 (top), plus DISABLED.
GoBildaPrismDriver.Artboard
ARTBOARD_0 … ARTBOARD_7.
Color
new Color(r, g, b) (0–255), or RED ORANGE YELLOW OLIVE GREEN CYAN BLUE TEAL MAGENTA PURPLE PINK WHITE TRANSPARENT.
Direction
Direction.Forward (toward higher indexes, clockwise for us) or Direction.Backward.
Reference

PrismAnimations

Every animation has setBrightness(0–100), setStartIndex(int), setStopIndex(int), and setIndexes(start, stop). By default it covers indexes 0–255 at 100% brightness. Periods are in milliseconds, and you can also call setPeriod(2, TimeUnit.SECONDS). Speeds go from 0.0 to 1.0. Hues are in degrees (0–360).

Solid(Color [, brightness] [, start, stop])
One color. setPrimaryColor(Color) or (r, g, b). Default RED.
Blink(primary, secondary, period, primaryColorPeriod)
Shows primary for primaryColorPeriod ms, then secondary for the rest of the period. Defaults BLUE / RED, 2000 / 1000.
Pulse(primary, secondary, period)
Fades smoothly between two colors. Defaults GREEN / RED, 1000.
SineWave(primary, secondary, period, speed, offset, direction)
A rolling wave that blends two colors. setOffset shifts the blend. Defaults RED / BLUE, 1000, 0.5, 0.5, Forward.
DroidScan(primary, secondary)
An "eye" sweeping back and forth. setEyeWidth, setTrailWidth, setSpeed, setDroidScanStyle(DroidScanStyle.NO_TAIL / FRONT_TAIL / BACK_TAIL / BOTH_TAIL).
Rainbow(startHue, stopHue, speed, direction, repeatAfter)
A scrolling hue gradient that repeats every repeatAfter LEDs. Defaults 0, 360, 0.5, Forward, 25.
Snakes(snakeLength, spacingBetween, repeatAfter, background, speed, direction, Color... colors)
Moving colored segments, one per color. Defaults 5, 2, 15, TRANSPARENT, 0.5, Backward, RED/WHITE/BLUE.
RainbowSnakes(startHue, stopHue, numberOfSnakes, snakeLength, spacingBetween, repeatAfter, background, speed, direction)
Snakes colored across a hue range.
Random(startHue, stopHue, speed)
Each LED changes to a random hue in the range. Default speed 0.1.
Sparkle(primary, secondary, period)
Random LEDs flash primary. setSparkleProbability(0–255). Defaults WHITE / TRANSPARENT, 100 ms, 16.
SingleFill(Color... colors)
Blocks of setPixelLength LEDs slide in and stack up until the range fills, then the next color starts. setStyle(SingleFillStyle.FillIn / FillOut).
PoliceLights()
Red / white / blue flashing. setPoliceLightsStyle(PoliceLightsStyle.Style1 / Style2 / Style3), setPrimary/Secondary/TertiaryColor.
On The Robot

Moving your code to the Control Hub

  1. Get goBILDA's Java driver for the Prism (four files: GoBildaPrismDriver.java, PrismAnimations.java, Color.java, Direction.java) from goBILDA's Prism product page or their GitHub. The examples here import them from org.firstinspires.ftc.teamcode.Prism. Change the imports if you put them in a different package.
  2. Plug the Prism into an I²C port on the Control Hub, and the LED chain into the Prism, with the top strip first.
  3. In the robot configuration, add an I²C device of type goBILDA® Prism RGB LED Driver and name it prism.
  4. Copy your OpMode into TeamCode, build, and run it from the Driver Station.
Honesty Check

Simulator vs. the real Prism

  • Matches the real driver: class, method, and enum names, constructor overloads, default values, 10 layers, 8 artboards, index ranges, and when an I²C write happens.
  • Approximate: how fast and exactly how the moving animations look (speed scaling, SineWave, SingleFill, PoliceLights styles, Sparkle probability). Use the robot to fine-tune.
  • Java subset: your code is translated to JavaScript. Fields, methods, if/switch/loops, arrays, simple enums, String.format, and ElapsedTime work. Lambdas, generic collections, inner classes, and java.util.Random don't. Dividing two ints only drops the decimals when the result goes straight into an int variable or an (int) cast.
